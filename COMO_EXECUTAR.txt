RAPPY FAST FOOD - COMO EXECUTAR NO WINDOWS

Este guia corresponde à configuração atual do repositório. Os serviços são executados pelo Docker; não é necessário instalar .NET, Flutter ou SQL Server diretamente no Windows.

REQUISITOS
  - Windows 10 (22H2) ou Windows 11, 64 bits.
  - Docker Desktop instalado e com o indicador "Engine running".
  - Virtualização habilitada e WSL 2 configurado (Docker Desktop pode orientar a instalação).
  - Internet na primeira execução para baixar imagens e dependências.

1. PREPARAR O PROJETO

  a) Baixe ou clone o repositório.
  b) Extraia o ZIP para uma pasta sem acentos, por exemplo C:\Projetos\rappy-fast-food.
  c) Abra essa pasta. O arquivo docker-compose.yml deve estar diretamente nela.
  d) Abra o Prompt de Comando nessa pasta: clique na barra de endereço do Explorador,
     digite cmd e pressione Enter.

2. CONFIGURAR O AMBIENTE

  No Prompt de Comando, crie o arquivo local .env:

      copy .env.example .env

  Abra o .env no Bloco de Notas e defina:
    MSSQL_SA_PASSWORD  senha forte para o administrador do SQL Server (sa).
    JWT_SECRET         chave aleatória longa para assinatura dos tokens da API.

  Para criar um administrador de demonstração, preencha também:
    DEMO_ADMIN_EMAIL      e-mail administrativo que você escolheu.
    DEMO_ADMIN_PASSWORD  senha própria com pelo menos 6 caracteres.

  Se DEMO_ADMIN_EMAIL e DEMO_ADMIN_PASSWORD ficarem vazios, o sistema não cria
  administrador automaticamente. Cliente e empresa podem ser cadastrados pela página
  /cadastro. Nunca publique o arquivo .env no GitHub.

3. INICIAR OS SERVIÇOS

  Confirme que o Docker Desktop mostra "Engine running" e execute:

      docker --version
      docker compose version
      docker compose up -d --build

  A primeira execução pode demorar, pois as imagens e dependências serão baixadas e os
  projetos serão compilados. Para acompanhar:

      docker compose ps -a
      docker compose logs -f db

  Estado esperado após a inicialização:
    db       Up (healthy)
    db-init  Exited (0)  [normal: executa os scripts SQL e encerra]
    api      Up
    web      Up
    mobile   Up

4. ACESSAR O SISTEMA

  Site (Web) ........ http://localhost:8081
  Aplicativo Web .... http://localhost:8082
  API (produtos) .... http://localhost:8080/api/produtos
  SQL Server ........ localhost,1433 (usuário sa; senha do .env)

  Contas de demonstração:
    Administrador: use o DEMO_ADMIN_EMAIL e DEMO_ADMIN_PASSWORD definidos no .env.
    Cliente: na página /cadastro, selecione Cliente e crie uma conta.
    Empresa: na página /cadastro, selecione Empresa e crie uma conta.

  Não existem senhas padrão publicadas neste projeto. A senha do administrador é lida
  localmente pelo DbSeeder a partir das variáveis do .env. As antigas contas de demonstração
  com e-mails admin@rappy.com, cliente@rappy.com e empresa@rappy.com são desativadas; seus
  registros relacionados são preservados.

5. ACESSAR PELO CELULAR (OPCIONAL)

  O celular e o PC precisam estar no mesmo Wi-Fi.
  a) Execute ipconfig e anote o Endereço IPv4 do adaptador Wi-Fi.
  b) Se necessário, libere as portas 8080, 8081 e 8082 no Firewall do Windows (PowerShell
     como Administrador):

      New-NetFirewallRule -DisplayName "Rappy Fast Food" -Direction Inbound -Protocol TCP -LocalPort 8080,8081,8082 -Action Allow

  c) No navegador do celular, use http://IP_DO_PC:8082 (aplicativo) ou
     http://IP_DO_PC:8081 (site). A disponibilidade depende da configuração de rede e firewall.

6. PARAR, INICIAR E PRESERVAR O BANCO

  Parar contêineres mantendo os dados:
      docker compose stop

  Iniciar novamente:
      docker compose up -d

  Remover contêineres e rede mantendo o volume:
      docker compose down

  ATENÇÃO: NÃO execute docker compose down -v se precisar preservar o banco. Esse comando
  remove o volume dbdata e pode apagar os dados armazenados no SQL Server.

  Para reconstruir após alterações no código:
      docker compose up -d --build

  Para aplicar alterações somente na API (por exemplo, configuração do administrador):
      docker compose up -d --build api

7. PROBLEMAS COMUNS

  - "docker" não é reconhecido:
      Feche e abra o terminal novamente. Confirme que o Docker Desktop está instalado.

  - "error during connect" ou "cannot find the file specified":
      Abra o Docker Desktop e aguarde "Engine running". Depois teste docker info.

  - SQL Server fica unhealthy ou os logs mostram erro 18456 para o usuário sa:
      A senha do volume existente pode ser diferente da senha atualmente escrita no .env.
      O SQL Server não troca a senha do sa só porque o .env mudou. Se souber a senha atual,
      conecte-se ao container e altere o login com sqlcmd, por exemplo:

      docker compose exec db /opt/mssql-tools18/bin/sqlcmd -C -S localhost -U sa -P "SENHA_ATUAL" -Q "ALTER LOGIN sa WITH PASSWORD = 'NOVA_SENHA'"

      Depois atualize MSSQL_SA_PASSWORD no .env para a mesma NOVA_SENHA e execute
      docker compose up -d. Não remova o volume para corrigir isso se precisar dos dados.

  - "port is already allocated":
      Outro serviço está usando a porta indicada (1433, 8080, 8081 ou 8082). Identifique-o
      antes de parar qualquer serviço; não apague o volume do banco.

  - Site/app abre, mas não carrega dados:
      Confira docker compose ps -a e consulte docker compose logs api.

  - Falha na inicialização dos scripts SQL:
      Consulte docker compose logs db-init e confirme que o SQL Server está healthy.

  - Credenciais administrativas não funcionam:
      Confira DEMO_ADMIN_EMAIL e DEMO_ADMIN_PASSWORD no .env e recrie a API com
      docker compose up -d --build api. O inicializador sincroniza a conta administrativa
      configurada no ambiente ao iniciar a API.
